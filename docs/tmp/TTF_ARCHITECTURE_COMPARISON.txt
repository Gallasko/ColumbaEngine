================================================================================
TTF TEXT RENDERING SYSTEM vs TEXTURE RENDERING SYSTEM - ARCHITECTURE COMPARISON
================================================================================

                          TEXTURE SYSTEM              TTF TEXT SYSTEM
                          ==============              ===============

COMPONENTS:
  Entity has:
    PositionComponent              PositionComponent
    Texture2DComponent             TTFText
                                   TTFTextCall (generated)

RENDER CALL STORAGE:
  Where stored:    System map                       Component vector
  Type:            Map<entityId → RenderCall>      Vector<RenderCall>
  Count/entity:    1                                N (per character)

SYSTEM DATA:
  Stores:          entityRenderCalls map            textUpdateQueue
                   entitiesInRenderGroup vector     charactersMap
                   textureUpdateSet                 currentLoadedMaterialId

INITIALIZATION:
  1. System created in application
  2. System::init() sets up materials
  3. Textures loaded separately
  4. No font registration needed

                                          1. System created in application
                                          2. System::init() sets up materials
                                          3. registerFont() called
                                          4. Atlas generated via FreeType
                                          5. Atlas uploaded to GPU

UPDATE TRIGGER:
  Events:          TextureChangedEvent              TTFTextChangedEvent
                   PositionComponentChangedEvent    PositionComponentChangedEvent
  Update style:    Direct map update                Queue + batch process

RENDER CALL CREATION:
  Method:          createRenderCall()               createRenderCall()
                   Returns: RenderCall              Returns: vector<RenderCall>
  Data layout:     11 floats                        15 floats
  Contains:        pos, size, rotation,             pos, size, rotation, color,
                   opacity, color                   UV coords

ASSET MANAGEMENT:
  Textures:        External image files             Generated atlases
  Per-font:        N/A                              Separate atlas + material
  Material reuse:  Via name lookup                  Via font name caching

KEY DIFFERENCE:
  ============================================================================
  Texture System stores ONE render call per entity in the SYSTEM
  TTF System stores MULTIPLE render calls per entity in a COMPONENT
  ============================================================================

WHY THE DIFFERENCE?
  - Texture: Single visual element = single call
  - TTF: Text with N characters = N separate glyph renders
    (Each needs different position, UV coordinates, possible color)

PERFORMANCE IMPLICATIONS:
  Texture:  1 entity = 1 render call = 1 draw (batched)
  TTF:      1 entity = N render calls = N draws (may batch if same material)

  "Hello World" (11 chars):
    - Texture: 1 render call
    - TTF: 11 render calls (but all use same material, so can batch)

ARCHITECTURAL INSIGHT:
  The TTFTextCall wrapper component is key:
  - Cleanly separates glyph data from text data
  - Allows system to iterate entities normally
  - Render calls live in component for ECS consistency
  - vs Texture2D which breaks ECS pattern (calls in system)
