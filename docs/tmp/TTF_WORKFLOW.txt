================================================================================
TTF TEXT RENDERING - COMPLETE WORKFLOW
================================================================================

PHASE 1: INITIALIZATION (Happens once at startup)
----------------------------------------------------

    application.cpp
         |
         v
    ecs.createSystem<TTFTextSystem>(masterRenderer)
         |
         v
    TTFTextSystem::init()
    ├─ Initialize FreeType library
    ├─ Set up material preset
    │  ├─ Shader: "ttfTexture"
    │  ├─ Texture count: 1
    │  └─ Mesh layout: {3, 2, 1, 1, 3, 1, 4}
    ├─ Register (PositionComponent, TTFText) group
    │  ├─ On add entity:
    │  │  └─ Push entity to textUpdateQueue
    │  └─ On remove entity:
    │     └─ Detach TTFTextCall component
    └─ Create FreeType context
         |
         v
    ttfSys->registerFont(fontPath, fontName, pixelSize)
    ├─ Create FreeType face for font file
    ├─ Allocate 1024x1024 glyph atlas
    ├─ For each character (32-126):
    │  ├─ Render glyph to FreeType bitmap
    │  ├─ Pack into atlas using rectangle packing
    │  ├─ Calculate UV coordinates
    │  └─ Store metadata in charactersMap[fontName][char]
    ├─ Create OpenGL texture from atlas
    │  ├─ glGenTextures(1, &texture)
    │  ├─ glTexImage2D(..., GL_RED, atlasBuffer)
    │  └─ Set texture parameters (LINEAR filter, CLAMP_TO_EDGE)
    └─ Register texture with MasterRenderer
         |
         v
    System ready for use


PHASE 2: ENTITY CREATION (When user creates text)
-------------------------------------------------

    User/Script
         |
         v
    makeTTFText(ecs, x, y, z, fontPath, text, scale, colors)
    ├─ Create entity
    ├─ Attach PositionComponent
    │  ├─ x, y, z (position)
    │  ├─ width, height (initialized from text metrics)
    │  └─ rotation, visible flags
    ├─ Attach UiAnchor (UI positioning)
    └─ Attach TTFText component
       ├─ text: "Hello"
       ├─ fontPath: "light"
       ├─ scale: 1.0
       ├─ colors: {255, 255, 255, 255}
       ├─ wrap: false
       ├─ spacing: 0
       └─ viewport: 0
         |
         v
    Group detects new entity (PositionComponent + TTFText)
         |
         v
    Group callback: addOnGroup()
    ├─ Push entity->id to textUpdateQueue
    └─ Set changed = true


PHASE 3: RENDER CALL GENERATION (Each frame when changed)
---------------------------------------------------------

    Engine frame loop
         |
         v
    TTFTextSystem::execute() [called if changed == true]
    |
    ├─ Step 1: Collect existing render calls
    |  ├─ Clear renderCallList
    |  ├─ Get all TTFTextCall components via view<TTFTextCall>()
    |  └─ For each TTFTextCall:
    |     └─ Add its .calls vector to renderCallList
    |
    ├─ Step 2: Process update queue
    |  └─ while (not textUpdateQueue.empty())
    |     ├─ Pop entity ID
    |     ├─ Get PositionComponent (ui)
    |     ├─ Get TTFText component (obj)
    |     ├─ Call createRenderCall(ui, obj)
    |     │   └─ Returns: vector<RenderCall> (one per glyph)
    |     └─ Update or create TTFTextCall component with calls
    |
    └─ Step 3: Mark ready for rendering
       ├─ finishChanges()
       │  ├─ changed = false
       │  └─ dirty = true
       └─ Return


PHASE 4: RENDER CALL CREATION - THE HEART
------------------------------------------

    createRenderCall(CompRef<PositionComponent> ui, CompRef<TTFText> obj)
    Returns: vector<RenderCall>
    
    Step A: Parse formatted text
    ├─ Input: "Hello\c{255,0,0,255} RED"
    ├─ Parse escape sequences:
    │  └─ \c{255,0,0,255} = color change command
    ├─ Split into segments:
    │  ├─ Segment 1: text="Hello", color={default}
    │  └─ Segment 2: text=" RED", color={255,0,0,255}
    └─ Output: vector<TTFText> segments with colors
    
    Step B: Layout calculation
    ├─ startX = ui->x
    ├─ startY = ui->y
    ├─ z = ui->z
    ├─ lineHeight = computeLineHeight(text, fontPath, scale)
    ├─ maxWidth = ui->width (or 10000 if no wrap)
    └─ Initialize currentX, currentY
    
    Step C: Per-character processing (for each segment)
    ├─ For each character in segment text:
    |  ├─ If character == ' ':
    |  |  └─ Advance X by space width
    |  |
    |  └─ Else (non-space):
    |     ├─ Check if start of word
    |     ├─ If yes: Calculate full word width
    |     ├─ Check if word would wrap
    |     |  └─ If yes: Y += lineHeight, X = startX
    |     ├─ Create glyph render call
    |     |  └─ createGlyphRenderCall(...)
    |     │      Returns: One RenderCall for this glyph
    |     │      
    |     │      RenderCall contains:
    |     │      ├─ key (bitfield):
    |     │      │  ├─ visibility: 1 bit
    |     │      │  ├─ render stage: 4 bits
    |     │      │  ├─ viewport: 3 bits
    |     │      │  ├─ opacity type: 2 bits (Additive)
    |     │      │  ├─ depth/Z: 24 bits
    |     │      │  └─ material ID: 30 bits
    |     │      │
    |     │      └─ data[15]:
    |     │         ├─ [0-2]: currentX + bearing.x, currentY - bearing.y + lineHeight, z
    |     │         ├─ [3-4]: glyph width * scale, glyph height * scale
    |     │         ├─ [5]: rotation
    |     │         ├─ [6]: opacity (255)
    |     │         ├─ [7-9]: RGB color from segment
    |     │         ├─ [10]: 1.0f (flag)
    |     │         ├─ [11-12]: UV top-left (from atlas)
    |     │         └─ [13-14]: UV bottom-right (from atlas)
    |     │
    |     └─ Append RenderCall to output vector
    |     └─ X += glyph advance
    
    Step D: Update text dimensions
    ├─ totalWidth = currentX - startX
    ├─ totalHeight = (currentY - startY) + lineHeight
    └─ Update obj->textWidth/Height and ui->width/height
    
    Step E: Return
    └─ Return vector of all RenderCall objects


PHASE 5: RENDERING (MasterRenderer takes over)
-----------------------------------------------

    MasterRenderer::render()
    ├─ Collect all renderCallLists from all systems
    ├─ TTFTextSystem contributes its renderCallList
    │  └─ Contains all RenderCall objects from all TTFTextCall components
    ├─ Sort all render calls by key (bitfield)
    │  └─ By visibility → stage → viewport → opacity → depth → material
    ├─ Batch calls with same material
    └─ For each batched group:
       ├─ Bind shader ("ttfTexture")
       ├─ Bind texture (font atlas)
       ├─ For each RenderCall in batch:
       │  ├─ Bind VAO (quad mesh)
       │  ├─ Set uniform: glyph position, size, color, UV
       │  └─ glDrawArrays(...) or glDrawElements(...)
       └─ GPU renders textured quad for that glyph


PHASE 6: RUNTIME UPDATES (When user modifies text)
--------------------------------------------------

    User/Script changes text:
    obj->setText("Hello World")
         |
         v
    TTFText::setText() checks if changed
    ├─ if (text != value) {
    │   ├─ text = value
    │   ├─ Send TTFTextChangedEvent{entityId}
    │   └─ }
         |
         v
    TTFTextSystem::onEvent(TTFTextChangedEvent event)
    ├─ onEventUpdate(event.id)
    │  ├─ Check if entity has TTFTextCall
    │  ├─ If yes: Push to textUpdateQueue
    │  └─ changed = true
         |
         v
    Next frame: execute() is called again
         |
         v
    (Repeat from PHASE 3)


KEY INSIGHTS:
=============

1. LAZY EVALUATION
   - Changes queue entity, not immediate regeneration
   - execute() runs once per frame
   - Batches multiple changes if they occur

2. COMPONENT SEPARATION
   - TTFText: User data (text, font, scale, color)
   - TTFTextCall: Generated data (render calls)
   - PositionComponent: Layout (x, y, width, height, z)

3. ATLAS CACHING
   - Each font has ONE atlas texture (1024x1024)
   - All glyphs from font share this texture
   - Atlas created once during registerFont()
   - Character metadata cached in charactersMap

4. MATERIAL REUSE
   - All glyphs from same font = same material
   - Material = shader + texture + uniforms
   - Allows GPU batching of render calls

5. RENDER CALL EXPLOSION
   - 100-character text = 100 render calls
   - But can batch if all same material
   - vs single texture = 1 render call

6. NO GLYPH CACHING
   - Render calls regenerated on every text change
   - Full rebuild of vector<RenderCall>
   - Could be optimized with dirty regions
