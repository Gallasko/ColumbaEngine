# For-In Loop Implementation

## Overview

This document describes the implementation of the for-in loop feature in the PG scripting language. The for-in loop provides a simpler, more intuitive way to iterate over table keys.

## Syntax

```pg
for (var key : table) {
    // body
}
```

## Implementation Strategy

The for-in loop is implemented as syntactic sugar that desugars to a regular for loop at compile time:

```pg
// Original for-in loop
for (var key : table) {
    body;
}

// Desugars to
{
    var __table = table;
    var __size = __table.size();
    for (var __i = 0; __i < __size; __i++) {
        var key = __table.at(__i);
        body;
    }
}
```

## New Opcodes

Two new opcodes were added to support this feature:

### OP_Table_Size

- **Purpose**: Get the number of fields in a table
- **Stack**: `[table] -> [size]`
- **Implementation**: `op_table_size()` in [vm.cpp:2761-2781](src/Engine/Compiler/vm.cpp#L2761-L2781)

### OP_Table_At

- **Purpose**: Get the key at a specific index in a table
- **Stack**: `[table, index] -> [key]`
- **Implementation**: `op_table_at()` in [vm.cpp:2783-2831](src/Engine/Compiler/vm.cpp#L2783-L2831)

## Compiler Changes

### Parser Changes ([cparser.cpp:947-1044](src/Engine/Compiler/cparser.cpp#L947-L1044))

The `forStatement()` function was modified to detect for-in loops and generate the appropriate bytecode:

1. Detect the `:` token after the variable name
2. Parse the table expression
3. Store the table as a hidden local `__table`
4. Get and store the table size as `__size`
5. Initialize loop counter `__i = 0`
6. Loop condition: `__i < __size`
7. For each iteration:
   - Begin a new scope for the key variable
   - Get the key at index `__i` using `OP_Table_At`
   - Declare and initialize the loop variable with the key
   - Execute the loop body
   - End the iteration scope (pops the key variable)
   - Increment `__i`
8. Loop back to condition check
9. End the outer scope (pops `__i`, `__size`, and `__table`)

### Chunk Changes ([chunk.h:94-95](src/Engine/Compiler/chunk.h#L94-L95))

Added the two new opcodes to the `OpCode` enum:
- `OP_Table_Size`
- `OP_Table_At`

Also updated `getInstructionSize()` to include these opcodes.

### Debug Output ([compiler_debug.cpp:462-466](src/Engine/Compiler/compiler_debug.cpp#L462-L466))

Added debug output support for the new opcodes in `disassembleInstruction()`.

## Features

### Nested Loops

The implementation supports nested for-in loops correctly because each iteration creates a new scope for the key variable:

```pg
var outer = [x: 1, y: 2];
for (var k1 : outer) {
    var inner = [a: 10, b: 20];
    for (var k2 : inner) {
        __dprint(k1);  // x, x, y, y
        __dprint(k2);  // a, b, a, b
    }
}
```

### Empty Tables

The implementation handles empty tables correctly - the loop body never executes:

```pg
var empty = [];
for (var key : empty) {
    __dprint(key);  // Never executed
}
```

### Accessing Values

Since the loop variable contains the key, you can access the corresponding value:

```pg
var table = [name: "Alice", age: 30];
for (var key : table) {
    __dprint(key);         // "name", "age"
    __dprint(table[key]);  // "Alice", 30
}
```

## Advantages Over Previous Approach

The previous implementation used `OP_Get_Iterator` and `OP_Iterator_Next` which had complex stack management issues, particularly with nested loops. The new approach:

1. **Simpler**: Desugars to a regular for loop, reusing existing loop infrastructure
2. **More robust**: Properly handles nested loops by using scopes
3. **Easier to debug**: The generated bytecode follows familiar patterns
4. **Maintainable**: Less complex stack manipulation logic

## Potential Future Improvements

1. **Iteration Order**: Currently follows the insertion order of the `std::unordered_map` used for table fields, which may not be consistent. Consider using an ordered map or tracking insertion order explicitly.

2. **for-in with value**: Could extend syntax to `for (var key, value : table)` to avoid the extra table lookup.

3. **Range-based for**: Could add support for `for (var i : 0..10)` for numeric ranges.
